## MODIFIED Requirements

### Requirement: Контейнеризованная локальная инфраструктура

Проект SHALL предоставлять compose-файл, который поднимает только инфраструктурные зависимости — MongoDB, SQS-совместимую очередь и S3-совместимое хранилище — без сервисов приложения (`backend`, `frontend`, `caddy`). Каждый сервис MUST публиковать порт на хосте, чтобы процессы, запущенные вне докера, могли к нему подключиться. Конкретная реализация S3-совместимого хранилища MUST оставаться деталью инфраструктуры: спецификация не закрепляет поставщика, а требования к ней ограничены объёмом S3 API, который использует бэкенд, — загрузка и скачивание объекта, удаление, presigned GET и multipart-загрузка.

#### Scenario: Поднятие инфраструктуры одной командой

- **WHEN** разработчик выполняет `pnpm infra` в чистом рабочем каталоге
- **THEN** запускаются контейнеры MongoDB, SQS-совместимой очереди и S3-совместимого хранилища, и ни один сервис приложения не стартует
- **AND** команда завершается успешно только после того, как все сервисы прошли healthcheck

#### Scenario: Инфраструктура доступна процессам на хосте

- **WHEN** инфраструктура запущена
- **THEN** MongoDB доступна на `localhost` по опубликованному порту, SQS-эндпоинт — на `http://localhost:4566`, а S3 — на `http://localhost:9000`
- **AND** бэкенд, запущенный на хосте через `pnpm dev`, подключается к ним без дополнительной настройки сети

#### Scenario: Образы инфраструктуры доступны для анонимной загрузки

- **WHEN** разработчик поднимает инфраструктуру на машине, где образы ещё не кэшированы, без `docker login`
- **THEN** все образы скачиваются из публичных реестров, и ни один из них не требует авторизации или подписки
- **AND** версия каждого образа закреплена явным тегом, а не плавающим `latest`

#### Scenario: Хранилище принимает запросы клиента без явного региона

- **WHEN** бэкенд обращается к локальному S3-хранилищу клиентом, который не задаёт регион явно
- **THEN** запросы проходят подпись и авторизацию без ошибки вида `AuthorizationHeaderMalformed`
- **AND** presigned-ссылка, выданная локальным хранилищем, открывается без дополнительной настройки клиента

### Requirement: Готовность очереди и бакета при старте

Инфраструктура SHALL самостоятельно создавать ресурсы, которые приложение ожидает найти готовыми: очередь исполнения сценариев с DLQ и бакет S3, имя которого задано в `S3_BUCKET`. Бутстрап MUST быть идемпотентным — повторный запуск на существующих томах не MUST завершаться ошибкой и не MUST терять данные. Создание бакета MUST происходить в рамках штатного старта самого хранилища и MUST NOT требовать отдельного одноразового контейнера или внешней CLI-утилиты.

#### Scenario: Очередь создаётся при первом старте

- **WHEN** LocalStack стартует впервые
- **THEN** создаются очереди `scenario-execution` (visibility timeout 7200 секунд) и `scenario-execution-dlq`, связанные redrive-политикой с `maxReceiveCount: 3`
- **AND** бэкенд, запущенный на хосте, успешно отправляет и получает сообщения по URL очереди из окружения

#### Scenario: Бакет создаётся при первом старте

- **WHEN** S3-совместимое хранилище стартует впервые
- **THEN** бакет с именем из `S3_BUCKET` существует до того, как инфраструктура будет объявлена готовой, и ключ доступа из локального профиля имеет права на чтение и запись в него
- **AND** загрузка файла из локально запущенного бэкенда проходит без ошибки «bucket does not exist»

#### Scenario: Поднятие инфраструктуры — одна команда без второго шага

- **WHEN** разработчик выполняет `pnpm infra`
- **THEN** готовность бакета достигается без запуска отдельного бутстрап-контейнера после старта хранилища
- **AND** команда завершается одним проходом, а её успешное завершение означает, что и очередь, и бакет готовы к работе

#### Scenario: Повторный запуск на существующих данных

- **WHEN** разработчик выполняет `pnpm infra` повторно, при уже существующих томах и созданных ресурсах
- **THEN** бутстрап завершается успешно, очередь и бакет сохраняются, а ранее записанные данные остаются на месте

### Requirement: Управление жизненным циклом инфраструктуры

Проект SHALL предоставлять команды остановки, просмотра логов и полного сброса состояния инфраструктуры. Сброс MUST удалять тома данных, чтобы среду можно было пересоздать детерминированно.

#### Scenario: Остановка инфраструктуры

- **WHEN** разработчик выполняет команду остановки
- **THEN** инфраструктурные контейнеры останавливаются, а тома с данными сохраняются
- **AND** последующий `pnpm infra` поднимает среду с прежними данными

#### Scenario: Полный сброс состояния

- **WHEN** разработчик выполняет команду сброса
- **THEN** удаляются контейнеры и все тома данных MongoDB и S3-совместимого хранилища, включая тома его метаданных
- **AND** следующий запуск инфраструктуры создаёт пустую БД, пустой бакет и очередь заново, без ручных шагов
