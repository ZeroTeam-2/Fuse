# scenario-execution — delta

## ADDED Requirements

### Requirement: Валидация тел запросов исполнения

API SHALL проверять тело каждого запроса исполнения по объявленному контракту
до любого изменения состояния:

- создание запуска — `scenarioId` обязателен и является непустой строкой,
  `inputs` опционален и является объектом;
- сабмит страницы шага — `stepIndex` обязателен и является неотрицательным
  целым, `data` обязателен и является объектом;
- сабмит входов шага — `stepIndex` обязателен и является неотрицательным
  целым, `values` обязателен и является объектом.

Тело, в котором обязательное поле отсутствует, поле имеет недопустимый тип или
присутствует неизвестное контракту поле, MUST отклоняться со статусом `400` и
описанием непрошедших проверку полей. Отклонённый запрос MUST NOT создавать
документ `Run`, MUST NOT изменять состояние существующего запуска и MUST NOT
отправлять сообщение в очередь исполнения. Неизвестные поля MUST NOT попадать
во входные данные запуска и в данные страницы — ни сохранёнными в `Run`, ни
переданными воркеру.

Контракт тела каждого эндпоинта исполнения SHALL быть опубликован в схеме API
(swagger) как именованная схема, чтобы клиенты могли генерировать по ней типы.

#### Scenario: Запуск без обязательного поля

- **WHEN** приходит `POST /api/runs` с телом `{}` (без `scenarioId`)
- **THEN** API отвечает `400` с указанием поля `scenarioId`, документ `Run` не
  создаётся и сообщение в очередь не отправляется

#### Scenario: Неизвестное поле в теле запуска

- **WHEN** приходит `POST /api/runs` с телом
  `{ "scenarioId": "...", "isAdmin": true }`
- **THEN** API отвечает `400`, запуск не создаётся, и поле `isAdmin` ни в каком
  виде не попадает в документ `Run`

#### Scenario: Неверный тип в сабмите страницы

- **WHEN** приходит `POST /api/runs/:id/page-submit` с телом
  `{ "stepIndex": "0", "data": {} }` или `{ "stepIndex": -1, "data": {} }`
- **THEN** API отвечает `400`, запуск остаётся в том же статусе и на том же
  шаге, данные страницы не сохраняются

#### Scenario: Неизвестное поле в сабмите входов

- **WHEN** запуск ждёт ввода (`waiting_input`) и приходит
  `POST /api/runs/:id/input-submit` с телом
  `{ "stepIndex": 0, "values": {}, "retryCount": 5 }`
- **THEN** API отвечает `400`, запуск остаётся в статусе `waiting_input`, и
  исполнение не продолжается

#### Scenario: Корректное тело исполняется как раньше

- **WHEN** приходит запрос исполнения с телом, соответствующим контракту
- **THEN** поведение не меняется: запуск создаётся и возвращается `runId`,
  сабмит страницы или входов продвигает исполнение
