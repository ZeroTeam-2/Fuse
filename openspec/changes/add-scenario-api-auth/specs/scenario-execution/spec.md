## ADDED Requirements

### Requirement: Инжект auth-заголовка из сценария
При исполнении шагов типа `api` и `periodic` с `authEnabled: true` worker MUST найти запись ключа сценария по `appId` шага и добавить соответствующий HTTP-заголовок к запросу (с учётом формата `bearer` или `raw`), если имя этого заголовка ещё не задано резолвнутыми входами шага.

Если после резолва маппингов/констант в `header` уже есть значение с тем же именем заголовка (сравнение без учёта регистра), worker MUST NOT перезаписывать его — явный маппинг шага побеждает scenario key. Подстановка шаблонов `{{token}}` в константах (включая `Bearer {{access_token}}`) MUST выполняться как раньше, до решения об инжекте.

#### Scenario: Инжект Bearer из authConfig
- **WHEN** у шага `authEnabled` true, в сценарии для его `appId` сохранён Bearer-токен, и Header Authorization не задан маппингом
- **THEN** worker отправляет запрос с заголовком `Authorization: Bearer <token>`

#### Scenario: Маппинг переопределяет ключ сценария
- **WHEN** у шага `authEnabled` true и одновременно константа/маппинг задаёт заголовок `Authorization`
- **THEN** worker использует значение из маппинга, а не из authConfig

#### Scenario: authEnabled выключен
- **WHEN** у шага `authEnabled` false и в сценарии есть ключ для поставщика
- **THEN** worker не добавляет заголовок из authConfig

### Requirement: Ошибка при включённом auth без ключа
Если у шага `authEnabled: true`, а записи ключа для `appId` нет или значение пустое, worker MUST завершить шаг доменной ошибкой до HTTP-вызова; `Run` переходит в `failed` с диагностикой, указывающей на необходимость настроить ключ на вкладке «Авторизация».

#### Scenario: Запуск без ключа при authEnabled
- **WHEN** шаг требует auth (`authEnabled` true), ключ поставщика не задан, и пользователь запускает сценарий
- **THEN** шаг падает с понятной ошибкой про отсутствующий ключ, без обращения к внешнему API

### Requirement: Секреты не попадают в артефакты запуска
Worker MUST NOT сохранять значения ключей сценария и сформированные auth-заголовки в `stepResults`, payload событий прогресса и тексты ошибок, возвращаемые клиенту.

#### Scenario: Ошибка upstream без echo секрета
- **WHEN** внешний API возвращает ошибку после запроса с инжектированным ключом
- **THEN** сообщение об ошибке запуска не содержит значения ключа
