## ADDED Requirements

### Requirement: Вкладка «Авторизация» рядом с «Окружения»
Редактор сценария SHALL содержать четыре вкладки: **«Основная»**, **«Настройка шагов»**, **«Окружения»**, **«Авторизация»**. Поведение вкладки «Авторизация» и хранение ключей задаются capability `scenario-api-auth`. Список поставщиков на «Авторизации» MUST строиться по тем же правилам, что и на «Окружениях» (поставщики из api/periodic-шагов).

#### Scenario: Четыре вкладки в редакторе
- **WHEN** владелец открывает редактор существующего сценария
- **THEN** доступны вкладки «Основная», «Настройка шагов», «Окружения» и «Авторизация»

### Requirement: Индикатор и секция auth у шага
Для шагов api и periodic панель настройки SHALL включать секцию аутентификации согласно `scenario-api-auth`. Список шагов MUST показывать визуальный индикатор (shield), когда у шага включён `authEnabled`. Явный маппинг входного поля с `loc: header` и тем же именем, что у ключа сценария, MUST оставаться доступным и при исполнении переопределять инжект (см. `scenario-execution`).

#### Scenario: Shield на шаге с auth
- **WHEN** у api-шага `authEnabled` равен true
- **THEN** в списке шагов у карточки отображается индикатор необходимости/включения аутентификации

#### Scenario: Header-маппинг остаётся
- **WHEN** пользователь задаёт для header-параметра `Authorization` константу или ссылку на выход предыдущего шага
- **THEN** маппинг сохраняется в шаге наряду с возможным ключом на вкладке «Авторизация»
