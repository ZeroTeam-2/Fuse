## MODIFIED Requirements

### Requirement: Страница карточки
Карточка сценария SHALL иметь вкладки: «Обзор» (описание в rich-формате, число запусков, число поставщиков API, число endpoints, категория, кнопка «Перейти к запуску»), «Запуск» и «Сервисы и endpoints» (список поставщиков API и задействованных endpoints с методами и путями).

Страница карточки SHALL быть публичной: гость видит её целиком, включая вкладку «Запуск» с превью шагов сценария. Публичное представление опубликованного сценария MUST включать его шаги — на них строятся панель запуска и playground, которые гость видит до входа. Сам запуск MUST требовать аутентификации (см. capability `auth-profile`).

Публичность шагов MUST NOT распространяться на их внутренние поля. Из каждого шага MUST вырезаться `consts` — словарь констант, который автор заполняет вручную и в котором штатно оказываются ключи API и токены (именно оттуда берётся `Authorization: Bearer …` при вызове провайдера). Из ответа MUST вырезаться `blockedReason`: это внутренняя диагностика о том, какое приложение удалено у автора. Идентификаторы `appId`/`endpointId` остаются — они и так публичны во вкладке «Сервисы и endpoints», и по ним рисуется превью шага.

Описание карточки рендерится из rich-text автора и MUST санитизироваться парсерным санитайзером (см. capability `security-headers`), а не разбором разметки регулярными выражениями.

#### Scenario: Просмотр обзора
- **WHEN** пользователь открывает карточку из каталога
- **THEN** система показывает вкладку «Обзор» с отрендеренным описанием и метриками карточки

#### Scenario: Гость смотрит вкладку «Запуск»
- **WHEN** неаутентифицированный пользователь открывает вкладку «Запуск» карточки
- **THEN** система показывает панель запуска с превью шагов сценария (не сообщение об ошибке доступа), но запуск остаётся недоступным до входа

#### Scenario: Публичный ответ не раскрывает константы шагов
- **WHEN** неаутентифицированный клиент запрашивает `GET /api/marketplace/:id` у сценария, в константах шага которого лежит `Authorization: Bearer <ключ>`
- **THEN** в ответе есть шаги (тип, название, страница), но нет ни одного поля `consts` и нет `blockedReason`, а панель запуска и playground продолжают работать

### Requirement: Поиск
Маркетплейс SHALL поддерживать текстовый поиск по названию карточки и имени провайдера. Поиск MUST обновлять счётчики дерева категорий и показывать пустое состояние «По вашему запросу ничего не найдено».

Пользовательский запрос MUST экранироваться перед подстановкой в `$regex` (либо поиск переводится на текстовый индекс). Сейчас строка из query попадает в регулярное выражение как есть — и в `getCatalog`, и в `getCategoryCounts`, то есть один запрос гостя без аутентификации заставляет базу выполнить присланный им паттерн.

#### Scenario: Пустой результат
- **WHEN** запрос не совпадает ни с одной карточкой
- **THEN** система показывает пустое состояние и нулевые счётчики, сбрасываемые очисткой запроса

#### Scenario: Патологический паттерн экранирован
- **WHEN** клиент отправляет `?search=(a%2B)%2B%24`
- **THEN** система ищет литеральную подстроку `(a+)+$`, отвечает пустым результатом за обычное время ответа и не отдаёт выполнение паттерна базе
