## MODIFIED Requirements

### Requirement: Карточка сценария
Система SHALL позволять создать сценарий (use-case карточку) с названием, обложкой (загрузка/drag-and-drop изображения), rich-text описанием для маркетплейса (жирный, курсив, подчёркивание, заголовки, код) и категорией из справочника с поиском. Tagline карточки MUST выводиться из первых ~90 символов текстового описания. Сценарий — самостоятельная сущность и MAY собирать шаги из разных API.

Массив `steps` хранится как `Mixed` и приходит в `PATCH` единым куском: DTO проверяет только то, что это массив, а структура шага держится на `assertValidPageSteps` и защите от циклов. Этого достаточно для корректности, но не ограничивает размер. Система MUST ограничивать число шагов в сценарии и объём одного шага перед записью: документ растёт пользовательским вводом, и без границы один запрос доводит документ сценария до потолка хранилища, после чего сценарий перестаёт открываться и чиниться через интерфейс.

#### Scenario: Создание сценария
- **WHEN** пользователь заполняет детали и нажимает «Создать сценарий»
- **THEN** система создаёт неопубликованный сценарий без шагов и открывает редактор шагов

#### Scenario: Редактирование метаданных
- **WHEN** пользователь меняет обложку, описание или категорию на вкладке «Основная»
- **THEN** изменения сохраняются и отражаются в карточке маркетплейса после публикации

#### Scenario: Слишком большой шаг отклонён
- **WHEN** пользователь сохраняет шаг, объём которого превышает заданную границу
- **THEN** система отвечает `400` с сообщением о превышении размера и не сохраняет шаг

### Requirement: Публикация сценария
Система SHALL позволять публиковать и скрывать сценарий выделенным эндпоинтом `PATCH /api/scenarios/:id/publish`. Публикация MUST требовать хотя бы один шаг и MUST блокироваться для сценария, помеченного `blocked` (шаг ссылается на удалённое приложение). Опубликованный сценарий появляется в маркетплейсе, скрытый — виден только владельцу.

Поле `published` MUST быть исключено из `UpdateScenarioDto`. Сейчас оно там есть, а `update()` пишет тело запроса как `$set: { ...dto }` — то есть `PATCH /api/scenarios/:id` с `{ "published": true }` публикует сценарий мимо обеих проверок: без шагов и с заблокированным приложением. Публикация MUST проходить только через выделенный эндпоинт.

#### Scenario: Публикация без шагов
- **WHEN** пользователь пытается опубликовать сценарий без шагов
- **THEN** система блокирует публикацию с подсказкой «Добавьте хотя бы один шаг»

#### Scenario: Публикация сценария с заблокированным приложением
- **WHEN** пользователь пытается опубликовать сценарий, помеченный `blocked`
- **THEN** система блокирует публикацию и называет причину

#### Scenario: Байпас публикации через PATCH заблокирован
- **WHEN** владелец отправляет `PATCH /api/scenarios/:id` с телом `{ "published": true }` на сценарий без шагов
- **THEN** система отвечает `400` (глобальный `ValidationPipe` с `forbidNonWhitelisted` отбивает неизвестное поле), и сценарий не публикуется

## ADDED Requirements

### Requirement: Проверка владельца на manual-inputs сценария
Эндпоинт `GET /api/scenarios/:id/manual-inputs` SHALL принимать `userId` из JWT и отдавать дескрипторы ручных вводов только владельцу сценария. Сейчас обработчик принимает один `:id` и не смотрит, кому сценарий принадлежит: любой аутентифицированный пользователь читает структуру входов чужого черновика — имена параметров, типы, обязательность, то есть схему непубличной интеграции.

Гостевой путь у этих данных отдельный и уже закрыт: публичная карточка берёт их через `GET /api/marketplace/:id/manual-inputs`, который проверяет `published`. Поэтому эндпоинт в `/api/scenarios/*` (весь контроллер под `JwtAuthGuard`) MUST быть именно владельческим, а не «владелец или опубликован».

#### Scenario: Владелец запрашивает входы своего черновика
- **WHEN** владелец отправляет `GET /api/scenarios/<свой-черновик>/manual-inputs`
- **THEN** система возвращает полный список дескрипторов

#### Scenario: Чужой черновик не отдаётся
- **WHEN** аутентифицированный пользователь отправляет `GET /api/scenarios/<чужой-черновик>/manual-inputs`
- **THEN** система отвечает `404`, не раскрывая ни структуру входов, ни сам факт существования сценария

#### Scenario: Гостевой путь продолжает работать
- **WHEN** неаутентифицированный пользователь открывает карточку опубликованного сценария
- **THEN** форма запуска строится по `GET /api/marketplace/:id/manual-inputs`, и изменение владельческого эндпоинта её не затрагивает
