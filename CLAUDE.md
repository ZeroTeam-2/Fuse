# Fuse — инструкции для агентов

## Граф кода (graphify)

В репозитории есть локальный граф кода: `graphify-out/graph.json` (~2200 узлов,
~4200 рёбер). Он строится локальным AST-разбором, без модели и без токенов, за
~6 секунд, и **не коммитится** (см. `.gitignore`).

Сборка и свежесть:

```bash
# Штатная пересборка в начале сессии: ~6 с, 0 токенов.
graphify extract . --code-only --no-cluster --force && graphify cluster-only . --no-label

graphify update .                 # быстрее (~4 с), но см. предупреждение ниже
```

**`update` даёт неполный граф.** Замер 27.10.2026 на этом репозитории: при
одинаковых итогах (2237 узлов, 4201 ребро) инкрементальная сборка теряет 125
рёбер, которые находит `extract --force` — в том числе
`app.module.ts → validateEnv()`, `.executeStep() → .executeScenarioStep()`,
`.diffEndpoints() → endpointKey()` и почти все внутрифайловые вызовы в
`apps/backend/test/*.spec.ts`. Для «что связано» этого хватает; для вывода
«никто не вызывает X» или «файл не используется» — только после `--force`.

`graphify-out/GRAPH_REPORT.md` хранит коммит сборки — сверяйте с
`git rev-parse HEAD`, прежде чем доверять срезу.

Документы (`*.md`, `openspec/`, `docs/`) и конфиги-JSON исключены в
`.graphifyignore`, поэтому `update` остаётся код-онли без флагов. Без этого
исключения `update` подтягивает 247 markdown-файлов и граф раздувается вдвое
(4234 узла против 2237), а документные узлы вытесняют код из срезов запросов.

### Протокол запроса

Без этих правил граф отвечает хуже `grep` — проверено замерами в другом
репозитории (ADR «Граф кода graphify»):

1. **Бюджет не ниже 8000**: `graphify query "..." --budget 8000`. Умолчание
   2000 режет срез до бесполезного.
2. **`--seed` по файлу — самый сильный рычаг.** Если известен хоть один файл
   рядом с темой, начинайте с него: `--seed apps/backend/src/execution/worker.service.ts`,
   а не с ключевых слов.
3. **Английские идентификаторы, не русские слова.** Матчер в graphify —
   подстрока без стемминга и синонимов: «воркер» даст ноль узлов, `worker`,
   `Run`, `Step`, `Gateway` — нужные. Список реальных токенов графа:
   `grep -o '"label": "[^"]*"' graphify-out/graph.json | sort -u`.
4. `graphify path "A" "B" --undirected` — направленный поиск часто не находит
   путь, который есть.
5. `graphify explain "X" --all` — без `--all` печатаются только 20 связей.
6. **Срез — подсказка, а не граница ответа.** Найденные файлы читайте
   целиком, отсутствие ребра не означает отсутствие связи (см. ниже).

### Что граф отвечает, а что нет

Отвечает: «что связано с этим файлом», «как данные идут от A к Б», «кто
вызывает этот метод», «что сломается, если тронуть X» (`graphify affected`,
`god-nodes`).

**Не отвечает** на «какой код реализует требование спеки»: рёбер от
`openspec/specs/**` к коду в графе нет (граф — только по коду, `--code-only`).
Для этого — `grep` по терминам требования.

### Чего граф не видит в этом репозитории

- **Автоимпорты Nuxt.** Компоненты, подключённые через шаблон
  (`<Button>`, `<ScenarioPageParagraph>`), в графе не связаны ни с чем.
  `apps/frontend/components/**`, `pages/**`, `layouts/**`, `plugins/**`,
  `middleware/**` выглядят изолированными — это артефакт, а не мёртвый код.
  Связи фронтенда проверяйте `git grep "<ComponentName"`.
- **Composables и stores** через автоимпорт (`useApi()`, `useRunSocket()`) —
  тоже без рёбер к местам использования.
- **DI NestJS** виден (конструкторы читаются), но `@Inject` по токену — нет.
- **Тесты**: `apps/backend/test/*.spec.ts` попадают в граф как файлы с
  импортами, но без символов (`describe/it` — анонимные колбэки).
